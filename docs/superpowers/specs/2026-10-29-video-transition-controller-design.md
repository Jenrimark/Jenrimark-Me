# Video Transition Controller Design

日期：2026-10-29

状态：设计已确认，尚未实现

## 目标

将首页四个相邻页面过渡从连续帧滚动改为原子视频播放：

- 首屏继续使用 0-10s 眼神跟随帧。
- 其他四个页面在稳定状态显示固定帧。
- 上滑播放下一个动作视频，下滑播放上一个动作视频。
- 一次手势只触发一个动作。
- 过渡视频播放期间丢弃所有新的导航输入。
- 视频结束并显示稳定帧后，才恢复输入。
- 用少量 MP4 文件替代 721 张连续帧的滚动请求和解码压力。

## 非目标

- 不支持在动作视频播放中途暂停、倒退或定位到任意帧。
- 不把首屏眼神跟随改成视频时间 scrub。
- 不改变顶部导航的直达页面行为。
- 不重新生成人物、背景或源视频素材。
- 不在本次设计中删除旧帧序列；旧序列保留为故障回退资产。

## 页面与稳定状态

页面顺序：

1. 初次见面：0-10s 眼神跟随
2. 学履：13s 稳定帧
3. 工作：18s 稳定帧
4. 作品集：26s 稳定帧
5. 认识一下：29s 稳定帧

24fps 帧号换算：

| 页面 | 源视频时间 | 稳定帧 |
|---|---:|---:|
| 学履 | 13.00s | 312 |
| 工作 | 18.00s | 432 |
| 作品集 | 26.00s | 624 |
| 认识一下 | 29.00s | 696 |

首屏没有单一稳定帧。离开首屏前，画面由 `storyGazeTime` 继续根据指针位置在 0-10s 内选择眼神帧。

## 过渡素材

每个动作生成正放和倒放两个 MP4，使用同一 H.264、yuv420p、24fps 视频规格，音频静音或不导出。

| 过渡 | 源范围 | 正放文件 | 倒放文件 | 页面播放时长 | 播放速率 |
|---|---:|---|---|---:|---:|
| 初次见面 -> 学履 | 10.00-12.00s | `action-01-forward.mp4` | `action-01-reverse.mp4` | 3.000s | 0.667x |
| 学履 -> 工作 | 14.50-18.00s | `action-02-forward.mp4` | `action-02-reverse.mp4` | 3.000s | 1.167x |
| 工作 -> 作品集 | 21.07-26.00s | `action-03-forward.mp4` | `action-03-reverse.mp4` | 4.000s | 1.240x |
| 作品集 -> 认识一下 | 26.00-29.00s | `action-04-forward.mp4` | `action-04-reverse.mp4` | 3.000s | 1.000x |

播放速率定义为 `素材自然时长 / 页面播放时长`。动作三当前素材包含 119 帧，自然时长约 4.958s。

## 转场桥接

每个过渡开始时，当前画面与视频首帧使用 200ms 交叉淡化。页面内容层同步在 200ms 内切换到目标页面。

| 过渡方向 | 开始桥接 | 结束桥接 |
|---|---|---|
| 首屏 -> 学履 | 当前眼神帧 -> 10s 视频首帧，淡化 200ms | 12s 视频末帧 -> 13s 稳定帧，硬跳 |
| 学履 -> 工作 | 13s 稳定帧 -> 14.5s 视频首帧，淡化 200ms | 18s 视频末帧 -> 18s 稳定帧 |
| 工作 -> 作品集 | 18s 稳定帧 -> 21.07s 视频首帧，淡化 200ms | 26s 视频末帧 -> 26s 稳定帧 |
| 作品集 -> 认识一下 | 26s 稳定帧 -> 26s 视频首帧 | 29s 视频末帧 -> 29s 稳定帧 |

反向过渡使用倒放视频，桥接规则镜像：

- 作品集 -> 工作：29s 稳定帧开始，倒放至 21.07s，再淡化到 18s 稳定帧。
- 工作 -> 学履：18s 稳定帧开始，倒放至 14.5s，再淡化到 13s 稳定帧。
- 学履 -> 首屏：13s 稳定帧淡化到 12s 反向视频首帧，倒放至 10s，再淡化到首屏直视帧并恢复眼神跟随。

## 状态机

```text
idle
  -> preparing
  -> blending
  -> playing
  -> settling
  -> idle

preparing / blending / playing / settling
  -> error
  -> settling
  -> idle
```

### 状态职责

- `idle`：显示稳定帧或首屏眼神帧，接受一次方向输入。
- `preparing`：锁定输入，解析相邻过渡，加载正放或倒放视频。
- `blending`：执行 200ms 画面和内容交叉淡化，准备视频播放。
- `playing`：按目标播放时长执行 `video.play()`，期间不接受输入。
- `settling`：监听 `ended`，显示目标稳定帧并等待一次绘制完成。
- `error`：视频加载或播放失败，执行稳定帧回退，然后回 `idle`。

输入锁覆盖 `preparing`、`blending`、`playing`、`settling` 和 `error` 处理过程。锁定期收到的滚轮、触摸、方向键和程序化过渡请求全部丢弃，不排队。

## 输入映射

- 向下：滚轮向下、触摸向上滑、`ArrowDown`、`PageDown`、`Space`、`Numpad2`
- 向上：滚轮向上、触摸向下滑、`ArrowUp`、`PageUp`、`Numpad8`
- 一次手势只产生一次方向请求。
- 手势必须满足最小垂直位移或滚轮阈值，避免触控板微小抖动触发。
- 只有 `idle` 状态可以进入 `preparing`。
- 页面边界外的方向请求直接丢弃。

顶部导航仍可直达稳定页面，但 `transitioning` 状态期间导航命令不能修改当前页面。

## 渲染结构

```text
scene-stage
  img.scene-stable-frame
  video.scene-transition-video
  div.scene-content-layer
```

- `scene-stable-frame` 显示稳定帧，首屏显示眼神帧。
- `scene-transition-video` 在转场期间叠在稳定帧上，使用 `object-fit: cover`。
- 视频使用单个 DOM 节点，动作之间复用。
- 视频属性：`muted`、`playsInline`、`preload` 按邻接状态设置。
- 页面内容层由 `data-page` 控制显隐，转场开始时进入目标页，转场结束时锁定目标页。

## 预加载策略

- 当前页面相邻的两个过渡：提前加载 forward 和 reverse。
- 其他过渡：只加载 metadata。
- 同一时刻最多保留一个活动视频节点。
- 每个视频配首帧、末帧 poster，用于淡化起点和加载失败时的视觉回退。
- 旧的 WebP 帧序列不进入正常加载路径，仅在视频错误时按需加载。

## 错误处理

- `canplay` 超时或 `video.error`：不阻塞页面，直接交叉淡化到目标稳定帧。
- `play()` 被浏览器拒绝：使用静音视频重试一次，仍失败则执行稳定帧回退。
- 页面隐藏：暂停播放并保持输入锁；重新显示后继续播放。
- 页面隐藏超过 2 秒：直接完成到目标稳定帧并解锁，避免永久卡在转场。
- 目标稳定帧解码失败：保留当前帧到下一次成功渲染，不显示空白背景。
- `prefers-reduced-motion`：跳过视频播放和播放速率调整，直接执行短淡化并切到目标稳定帧。

## 数据模型

```ts
type TransitionSpec = {
  id: string;
  fromPage: number;
  toPage: number;
  sourceRange: [number, number];
  playbackDurationMs: number;
  forwardSrc: string;
  reverseSrc: string;
  playbackRate: number;
  startBlendMs: 200;
  endHoldFrame: number;
};
```

`sourceRange` 只描述源视频素材位置，`playbackDurationMs` 只描述页面过渡播放时长。两者不得互相替代。

## 验收标准

1. 一次上滑或下滑只触发一个相邻动作视频。
2. 视频播放期间所有方向输入被丢弃，不会加速、反向或切换页面。
3. 正放和倒放均能完整播放并正确落到对应稳定帧。
4. 四个过渡的页面播放时长分别严格为 3s、3s、4s、3s。
5. 转场开始时内容层完成 200ms 交叉淡化。
6. 首屏眼神跟随保持可用，方向路径仍为直视、右、上、左、回到直视。
7. 稳定页准确显示 13s、18s、26s、29s 帧。
8. 视频加载失败、减少动态效果和页面隐藏场景不会把页面锁死。
9. 正常路径不再请求 721 张故事帧，只请求 8 个动作视频和稳定帧。
10. 旧帧序列作为故障回退时仍能显示稳定页面。

## 性能验收

- 正常转场期间使用一个活动视频元素。
- 只预加载当前页相邻视频。
- 记录首屏请求总数、转场请求总数、传输字节数、视频解码错误率和输入锁最长持续时间。
- 目标是将故事转场从数百个帧请求降为 8 个视频文件，并让每次动作的请求和解码次数固定。
