# 首屏眼神跟随加载优化

## 基线与回退点

- Git 基线：`b9bc189`，优化前工作区干净。
- 回退标记：`checkpoint/gaze-before-2026-10-30`。
- 线上地址：`https://me.jenrimark.cn/`。
- 素材：241 张 1280×720 WebP，合计约 27.35 MiB。
- 2026-10-30，Chrome 1440×900、240 次/约 4 秒的连续指针移动：首次线上测试只有 1 次当前图片成功解码，231 个图片请求取消；重复测试仅 11 次成功。
- 保持原始图片、仅从本地返回图片字节的对照测试：两轮均 240 次成功、零取消；解码耗时的第 95 百分位分别为 10.6 ms、8.8 ms，未出现主线程长任务。
- 线上图片响应 `Cache-Control: public, max-age=0`。

## 目标

保留原有图片字节、分辨率、眼神映射和页面转场，消除快速移动指针时反复替换可见图片地址所造成的下载取消。

## 已确定的设计

使用一个有并发上限的帧缓存，把压缩图片获取、离屏解码、可见帧显示分离。指针事件只改变目标帧，浏览器绘制周期显示已经准备好的图片；加载中的旧目标继续完成并进入缓存。常用眼神与目标邻近帧优先，其他压缩图片在后台逐步预取。压缩数据最多保留整个素材集，离屏解码缓存限额 24 帧，显示中的帧在淘汰时受到保护。组件卸载时终止剩余请求并释放对象 URL。

鼠标悬停设备启用后台眼神资源预取；触屏设备继续使用原有静态图片和视频，不额外下载整套鼠标交互帧。离开首屏后不再显示眼神帧，返回首屏复用已经获取的资源。失败的帧最多重试一次，保留当前可见图片。

素材目录使用图片内容的 SHA-256 摘要作为版本，配置一年不可变缓存。版本变化必须产生新路径；场景 JSON 保持可更新。部署可选资源源站配置，为后续 OSS/CDN 接入提供统一入口，不改变图片编码。

## 验证

1. 延迟完成多个帧请求，确认快速更换目标不会取消先前下载；优先显示最新已准备好的目标。
2. 请求去重、下载/解码并发上限、24 帧缓存上限、可见帧保护、失败恢复及卸载释放均有测试。
3. 生产构建中验证版本图片的缓存响应、场景 JSON 更新策略以及原图摘要。
4. 浏览器使用真实组件和延迟图片响应重放指针移动，分别测首次和缓存后的跟随；确认下载取消消失，缓存后的交互保持流畅。
5. 保留首屏和后续页面的稳定帧、视频切换及回到首屏的检查。

## 云侧范围

优先使用现有云资源。2026-10-30 的只读查询返回 `CdnServiceNotFound`：当前账户未开通 CDN。需要新增收费服务时先准备精确配置及报价，再取得用户确认。购买前不修改网站现有 DNS 路由。
